# Astera 最終視覺系統設計規格

日期：2026-08-02  
狀態：待 Owner 審閱  
適用範圍：Astera 前台、會員中心、付款流程、訂單介面與後台視覺基礎

## 1. 文件定位

本文件將 Astera 目前已確認的品牌方向整理成可供設計與前端共同使用的視覺規範。

本文件的色彩規範取代 `docs/19_Astera_UIUX_Design_Handoff_v1.1.md` 第 4.2 節原有的 Stone Grey 色票；其餘未被本文件覆蓋的資訊架構、會員流程、Campaign 規則與付款規則仍以原交接文件及 `docs/22_Astera_OMS_Complete_Product_Requirements.md` 為準。

Astera 的視覺定位為：

> 高級收藏品牌的骨架，帶有藝人與 GL 企劃的情緒，同時具備會員服務與銀行匯款流程所需的可靠感。

## 2. 設計語氣

- Calm：安靜、低干擾，不使用促銷商城式堆疊。
- Refined：留白、細緻邊界、克制的品牌色。
- Collection-oriented：商品與藝人企劃是視覺主角。
- Approachable：不過度冷淡，使用粉紅與低彩度綠提供溫度。
- Trustworthy：付款、銀行帳戶、訂單狀態必須清楚且不依賴顏色猜測。

避免：

- 大面積高飽和色塊。
- 同一區塊同時使用多個強烈 accent。
- 假促銷、假熱門、無依據的推薦標籤。
- 尚未實作的付款方式或客服承諾。
- 為了裝飾而加入沒有操作意義的按鈕與圖示。

## 4. 顏色角色規則

Astera 不採用「五色平均分配」。每個顏色只負責一種主要工作：

1. `#20242B` 建立整個網站的安靜骨架。
2. `#6E4E64` 建立 Astera 的品牌記憶點。
3. `#466060` 傳達會員、付款與服務可靠感。
4. `#F8C7CC` 傳達限定企劃與 GL 情緒。
5. `#81A684` 協助分類與內容分層。

### 4.1 主要 CTA

主要 CTA 使用 `#6E4E64`，例如：

- `使用 Google 登入`
- `加入購物車`
- `立即處理`
- `確認付款回報`

CTA hover、focus 與 pressed 可轉為 `#20242B`，但不能只靠顏色變化表達已完成狀態。

### 4.2 會員與付款功能

會員、付款、銀行帳戶與對帳資訊使用 `#466060`，例如：

- `銀行帳戶已認證`
- `可用於回報付款`
- 付款流程的區段標題與說明連結
- 會員中心的服務型提示

正式成功、錯誤、警告仍需使用獨立的語意色系與文字／圖示，不把品牌色直接當成所有狀態色。

### 4.3 Campaign 與商品分類

- `#F8C7CC` 只用於限定企劃、GL 活動、活動提示或柔和背景，不用來表示錯誤或付款失敗。
- `#81A684` 用於商品分類與低優先 Badge，例如 `現貨`、`預購`、`會員預購`；標籤文字使用深色，不能使用低對比白字。
- 商品圖片本身可使用各自的藝術色彩，不必被品牌色濾鏡統一覆蓋。

## 5. 版面與元件語言

### 5.1 基本結構

- 頁面以 `color.page` 為背景。
- 卡片使用 `color.surface`，以細邊框區隔，不使用厚重陰影。
- 主要內容保留大面積留白，讓商品圖片與結單資訊成為視覺焦點。
- 桌面 Header 使用白色表面與細分隔線，Logo 使用深礦墨與襯線字體。

### 5.2 圓角與陰影

| 元件 | 規格 |
| --- | --- |
| 大區塊卡片 | `12px` |
| 商品／Campaign 卡片 | `10px` |
| 商品圖片 | `8px` 或跟隨卡片 |
| Button | `8px` |
| Badge／Filter chip | `999px` 或 `6px` |

陰影只用於 hover、下拉選單、Dialog 與高層級浮層；一般卡片以邊框和背景差異建立層次。

### 5.3 字體

- ASTERA Logo：襯線字體，呈現收藏與編輯感。
- UI、正文與表單：清晰的無襯線字體，中文閱讀優先。
- 正文不使用過細字重。
- 金額、數量與倒數使用 tabular numbers，避免數字變動造成跳動。
- 主要頁面標題可使用較大的襯線字體，功能型後台標題維持無襯線。

## 6. 主要頁面套用方式

### 6.1 未登入首頁

- 背景使用 `#F7F3F2`，Header 與商品卡使用白色。
- Logo、導覽與一般文字使用 `#20242B`。
- `使用 Google 登入` 使用 `#6E4E64`。
- 最新販售區的限定企劃標籤可使用 `#F8C7CC`。
- 商品狀態標籤可使用 `#81A684`，但不讓所有商品卡同時出現多個彩色 Badge。

整體應接近「收藏選物店首頁」，不是促銷 Landing Page。

### 6.2 Member Dashboard

- 待處理事項的主要操作使用 `#6E4E64`。
- 銀行帳戶與付款服務提示使用 `#466060`。
- 限定企劃或活動提醒使用 `#F8C7CC`。
- 沒有待辦事項時，保持空白與清楚空狀態，不用彩色填滿版面。
- Dashboard 桌面維持左欄任務、右欄即將結單與最新販售；手機預覽使用橫向滑動。

### 6.3 商品列表與詳情

- 正式商品列表手機一排 2 個。
- 商品圖片固定 `4:5`，預留尺寸避免載入跳動。
- 商品名稱、價格與結單資訊使用深色／次要文字層級。
- `預購`、`現貨`、`會員預購` 等 Badge 使用 `#81A684` 或中性樣式，不全部使用品牌紫。
- 加入購物車使用 `#6E4E64`。

### 6.4 購物車與付款回報

- 付款流程的步驟標題、銀行帳戶卡片與說明連結使用 `#466060`。
- 確認送出與主要操作使用 `#6E4E64`。
- 付款截止提醒需搭配文字與圖示，不能只變成粉紅或綠色。
- 未支援的刷卡、電子支付與多元付款不得出現在介面。

### 6.5 後台

- 後台維持較高資訊密度，但仍使用相同 Token。
- 背景以 `#F7F3F2` 或白色為主，表格文字使用 `#20242B`。
- 主要批次操作使用 `#6E4E64`；篩選、付款與資料匯入工具可使用 `#466060`。
- 不在後台使用大面積粉紅或鼠尾草綠；彩色只服務於狀態與操作分組。

## 7. 結單與狀態可及性

結單資訊是購買決策資訊，所有商品卡、Campaign、詳情、購物車與會員訂單都要清楚顯示。

狀態至少同時提供：

- 文字，例如 `剩 2 天｜8/10 結單`。
- 圖示或可辨識的前綴。
- 顏色作為輔助，不作唯一訊息來源。

所有文字與背景組合需通過 WCAG AA 對比檢查；主要文字與 CTA 不得使用低對比的中灰或白字。

## 8. 互動與動態

- Button、Chip、Card hover 使用 `150-200ms` 顏色／透明度過渡。
- Focus 必須可見，不能以移除 outline 取代設計。
- 不使用自動播放輪播、飛入式促銷 Banner 或大幅跳動卡片。
- 支援 `prefers-reduced-motion`。
- Icon-only 操作必須有 `aria-label`，觸控目標至少 `44×44px`。

## 9. 驗收條件

完成正式前端前，至少確認：

1. 主要頁面不再使用舊 `#9A6F5E` 作為品牌主色。
2. 一般頁面不會同時出現五種強烈色彩。
3. Google 登入與購物操作使用梅霧紫。
4. 銀行帳戶與付款服務區使用深青色。
5. Pink 與 Sage 不承擔錯誤、逾期或成功的唯一語意。
6. 商品圖片、結單日期與價格仍是商品卡的主要視覺層級。
7. 手機商品列表一排 2 個，Dashboard 預覽橫向滑動。
8. 所有狀態都同時有文字或圖示，不只依賴顏色。
9. 桌面、平板、手機都有可讀且可操作的 focus 與觸控狀態。

## 10. 不在本文件內定案的項目

以下仍需另行確認，不由本色彩規範推導：

- 最終字體家族與字體載入方式。
- Icon library。
- 匯款資料回報欄位與附件規則。
- Campaign 分類樹與藝人／CP／劇集關聯模型。
- 後台完整權限分級與工作台資料密度。
- 海外配送與付款方式。
