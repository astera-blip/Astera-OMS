# Astera UI/UX 設計交接文件 v1.1

## 1. 專案定位

Astera 是一個以泰國藝人、GL、官方周邊及收藏商品為核心的會員制代購電商平台。

Astera 不是一般綜合商城，也不採用 Shopee、momo、PChome 那種促銷導向視覺。整體體驗應介於：

> 品牌官網 x 收藏選物店 x 會員訂單管理平台

核心體驗不是單純展示商品，而是幫會員快速掌握：

1. 今天有哪些事情需要處理。
2. 哪些 Campaign 或商品即將結單。
3. 如何找到自己關注的販售活動與商品。
4. 如何清楚掌握訂單、付款、候補與通知狀態。

MVP 已確認限制：

- 會員一定要登入才能下單。
- 登入方式只支援 Google 登入。
- 付款方式只支援銀行匯款。
- 同一個 Campaign 內的商品使用相同截止時間。
- 候補流程需要納入 Dashboard、通知與訂單狀態。
- 後台 UI 需要納入本文件，但細節允許後續補充。

## 2. 核心 UX 原則

### 2.1 時間導向

一般電商主要回答「我要買什麼？」Astera 還必須回答「我還有多少時間可以下單？」

因此結單日期與剩餘時間是購買決策資訊，不能只放在 Tooltip、商品詳情頁或活動頁。

商品卡、Campaign 卡、商品詳情頁、購物車、會員訂單頁，都必須清楚顯示結單狀態。

Deadline 顯示規則：

| 條件 | 顯示文案 | 視覺層級 |
| --- | --- | --- |
| 7 天以上 | `8/20 結單` | 一般 |
| 4-7 天 | `剩 5 天｜8/20 結單` | 一般偏提醒 |
| 1-3 天 | `剩 2 天｜8/20 結單` | 警示 |
| 小於 24 小時 | `剩 X 小時｜今日結單` | 高警示 |
| 截止當日但未到時間 | `今日結單｜23:59 截止` | 高警示 |
| 已超過截止時間 | `已截止` | 停用 |

計算規則：

- 所有時間以 `Asia/Taipei` 為準。
- Campaign 有統一截止時間，商品若屬於 Campaign，優先使用 Campaign 截止時間。
- 沒有 Campaign 的商品可使用商品自己的截止時間。
- 已截止商品不可加入購物車。
- 已在購物車中的商品若截止，購物車需顯示不可結帳狀態與移除提示。

### 2.2 活動導向

Campaign 是一級瀏覽入口，例如：

- INVISIBLE FENCE
- GMMTV FAN DAY
- LingOrm Official Goods

但不是所有商品都一定屬於 Campaign，因此 Campaign 是選填關聯。

網站需保留三種入口：

- 販售活動：依 Campaign 瀏覽。
- 所有商品：包含無 Campaign 商品。
- 現貨商品：快速瀏覽現貨。

### 2.3 會員導向

Astera 的會員首頁是 Member Dashboard，不是促銷首頁。

Dashboard 優先順序：

1. 有待處理事項時：今天需要處理。
2. 沒有待處理事項時：即將結單。
3. 通知中心。
4. 最新販售活動。
5. 一般商品探索。

如果某區沒有資料，不應硬塞其他不相關內容，而應顯示清楚空狀態。

## 3. 登入前與登入後首頁

### 3.1 未登入首頁

目的：

- 建立品牌印象。
- 說明 Astera 是會員制代購平台。
- 展示即將結單、最新 Campaign、最新商品與公告。
- 引導使用者使用 Google 登入。

未登入首頁主要 CTA：

- `使用 Google 登入`
- `查看販售活動`

未登入使用者可瀏覽商品與活動，但下單、加入購物車、收藏、查看會員中心時，必須導向 Google 登入。

避免文案：

- `立即註冊`，除非流程實際存在非 Google 註冊。
- `多元付款`，MVP 僅支援銀行匯款。

### 3.2 登入後首頁

登入後首頁定位為會員工作台。

首頁主要協助會員處理：

- 待付款。
- 待補款。
- 候補取得資格。
- 候補資格即將失效。
- 付款待確認。
- 收件資料待補。
- 訂單修改確認。
- 有期限的系統要求。

## 4. 品牌視覺方向

### 4.1 設計關鍵字

- Minimal
- Calm
- Refined
- Comfortable
- Collection-oriented
- Gallery-like
- Premium but approachable

會員應感受到乾淨、舒服、容易找到重要資訊，而不是商品很多、促銷很多、不知道該先看哪裡。

### 4.2 色彩 Token

採用 Stone Grey / 暖灰米白方向，但需避免整體過度單色。可使用少量低飽和品牌 accent，用於主要 CTA、焦點狀態與重要 Badge。

基礎色票：

| Token | 用途 | 建議色 |
| --- | --- | --- |
| `surfacePage` | 頁面背景 | `#F5F5F3` |
| `surfaceCard` | 主要卡片 | `#FBFBFA` |
| `surfaceSubtle` | 次層卡片 | `#F0EFEC` |
| `textPrimary` | 主文字 | `#222222` |
| `textSecondary` | 次文字 | `#6B6B68` |
| `borderSubtle` | 邊框 / 分隔線 | `#DDDDD9` |
| `buttonPrimary` | 主要按鈕 | `#2B2927` |
| `iconMuted` | 圖示主色 | `#8B8175` |
| `accentBrand` | 品牌點綴 | `#9A6F5E` |

狀態色票需由設計師做對比檢查，文字對比至少達 WCAG AA：

| Token | 用途 | 視覺方向 |
| --- | --- | --- |
| `statusUrgent` | 今日截止、付款即將到期 | 低飽和磚紅 |
| `statusWarning` | 3 天內截止、候補資格即將失效 | 低飽和橘棕 |
| `statusPending` | 付款待確認、處理中 | 灰藍 |
| `statusSuccess` | 已完成、已確認 | 鼠尾草綠 |
| `statusInfo` | 一般通知 | 暖灰棕 |
| `statusDisabled` | 已截止、不可操作 | 灰階低對比但需可讀 |

### 4.3 字體方向

- ASTERA Logo：襯線字體，呈現收藏品牌感。
- UI 與正文：清晰無襯線，中文閱讀性優先。
- 正文不使用過細字重。
- 數字可稍微放大，並使用 tabular numbers，避免價格與倒數造成版面跳動。

品牌標語：

> Collect. Preserve. Remember.

### 4.4 圓角、陰影與邊框

建議收斂成固定規格：

| 元件 | 圓角 |
| --- | --- |
| 大區塊卡片 | `12px` |
| 商品卡 / 活動卡 | `10px` |
| 圖片 | `8px` 或跟隨卡片 |
| Badge | `999px` 或 `6px` |
| Button | `8px` |

陰影只用於 hover 或高層級浮層，不使用厚重浮動卡片效果。

## 5. 登入後 Dashboard 結構

### 5.1 桌面主網格

大桌面採用左側任務欄與右側內容欄：

- `>=1280px`：左 32% / 右 68%。
- `1024-1279px`：左欄至少 `320px`，右欄使用剩餘空間。
- `<1024px`：改為單欄上下排列。

欄位間距：

- 桌面：`16-20px`
- 平板 / 手機：`12-16px`

桌面結構：

```text
┌──────────── 左欄 ────────────┬──────────────── 右欄 ────────────────┐
│ 今天需要處理                │ 即將結單                            │
├─────────────────────────────┼─────────────────────────────────────┤
│ 通知中心                    │ 最新販售活動                        │
└─────────────────────────────┴─────────────────────────────────────┘
```

### 5.2 上方會員摘要列

摘要列是一張 100% 寬度完整卡片，不拆成兩張。

設計規格：

- 高度：`90-100px`
- 外觀不顯示 32% / 68% 分界線。
- 內部仍需對齊下方欄位。
- 左側顯示歡迎資訊。
- 右側四個摘要指標需落在下方右欄水平範圍內。
- 四個指標平均分配，可使用淡分隔線。

內容：

```text
歡迎回來，Tin
今天也一起享受收藏的樂趣吧！
```

摘要指標：

1. 待付款
2. 未完成訂單
3. 候補通知
4. 新通知

建議尺寸：

- 摘要圖示：`20-22px`
- 指標數字：`26-28px`
- 標籤文字：`13-14px`
- 圖示底座如有使用：`40-44px`

## 6. 左欄元件

### 6.1 今天需要處理

這是會員 To-do List，不是一般訂單列表。

首頁最多顯示三筆，超過顯示 `查看更多`。

排序優先順序：

1. 已逾期但仍可處理。
2. 24 小時內到期。
3. 3 天內到期。
4. 候補取得資格。
5. 待付款 / 待補款。
6. 付款待確認。
7. 收件資料待補。
8. 其他通知。

單筆內容：

- 狀態圖示。
- 任務類型。
- 商品、Campaign 或事件名稱。
- 截止時間 / 提交時間。
- 一個主要操作按鈕。

候補任務狀態：

| 狀態 | 顯示重點 | 操作 |
| --- | --- | --- |
| 候補中 | 等待釋出名額 | 查看詳情 |
| 取得資格 | 需在期限內確認或付款 | 立即處理 |
| 即將失效 | 強提醒截止時間 | 立即處理 |
| 候補失敗 | 說明未取得資格 | 查看詳情 |

### 6.2 通知中心

首頁顯示三筆通知，不應比今天需要處理更搶眼。

通知分類：

- 訂單通知。
- 付款通知。
- 候補通知。
- 系統通知。
- 公告。

每筆包含：

- 類型標籤。
- 簡短通知內容。
- 日期時間。
- 右側箭頭。

## 7. 右欄元件

### 7.1 即將結單

登入後 Dashboard 右欄第一順位。

桌面版預覽三張商品卡；正式商品列表才使用五欄。

Dashboard 商品卡包含：

- 剩餘時間 Badge。
- 商品圖片。
- 商品名稱。
- 價格。
- 結單日期。
- 加入購物車。
- 收藏。

手機 Dashboard 使用橫向滑動卡片，不使用手機雙欄網格。

### 7.2 最新販售活動

顯示三張 Campaign 卡。

Campaign 卡包含：

- 活動名稱。
- 活動主圖。
- 販售期間。
- 結單倒數。
- 商品數量。
- 查看活動。
- `NEW` Badge，僅在確實為新活動時顯示。

沒有 Campaign 的商品不出現在此區，但仍可出現在所有商品、即將結單與現貨商品。

## 8. 商品列表頁

商品列表需支援篩選、排序與狀態顯示。

商品格線：

- 大桌面：一排 5 個。
- 一般桌面：一排 4-5 個，依容器寬度調整。
- 平板：一排 3 個。
- 手機：正式商品列表一排 2 個。

商品圖片：

- 固定 `4:5`。
- 使用穩定 aspect ratio，避免載入時版面跳動。
- 商品圖不應過大，桌面建議約 `210-230px`。
- 使用 Next.js Image 時需設定尺寸與 remotePatterns。

商品卡必備資訊：

- 商品圖片。
- 商品名稱。
- 價格。
- 結單資訊。
- 加入購物車。
- 收藏。

可選 Badge：

- NEW
- 預購
- 現貨
- 追加
- 最後機會

不是每張商品卡都需要 Badge。

暫定篩選模型：

- Campaign。
- 商品狀態：預購 / 現貨 / 已截止。
- 結單時間：今日 / 3 天內 / 7 天內 / 全部。
- 價格區間。
- 收藏狀態。

待確認分類模型：

- 是否需要藝人、CP、劇集、品牌、商品類型等分類。
- 若需要，建議先做成可選 tag，不要太早固定成複雜分類樹。

## 9. 販售活動頁

Campaign 是一級頁面。

Campaign 頁面內容：

1. 活動名稱。
2. 活動簡介。
3. 結單倒數。
4. 完整結單日期。
5. 商品數量。
6. 商品列表。

同一 Campaign 內商品使用同一截止時間。

不需要過大的 Hero Banner。活動介紹不能佔用太多首屏空間，商品列表需在第一屏或接近第一屏的位置露出。

## 10. 商品詳情頁

桌面版：

- 左側：主要商品圖片。
- 右側：購買資訊。

手機版：

- 單欄。
- 商品圖片在上，購買資訊在下。
- 加入購物車 CTA 可視情況使用 sticky bottom，但需避免遮住內容。

資訊包含：

- 商品名稱。
- 價格。
- 所屬 Campaign，若有。
- 結單日期與剩餘時間。
- Variant / 尺寸。
- 數量。
- 加入購物車。
- 收藏。
- 商品說明。

避免加入：

- 大量推薦商品。
- 猜你喜歡。
- 假熱門排行。
- 無實際邏輯的促銷資訊。
- 影響會員選購的廣告 Banner。

## 11. 購物車與付款 UX

MVP 付款方式只支援銀行匯款，因此付款流程必須誠實呈現。

購物車需顯示：

- 商品名稱。
- 商品圖片。
- 數量。
- 單價與小計。
- 結單狀態。
- 是否仍可結帳。

若商品已截止：

- 禁止結帳。
- 顯示 `此商品已截止，請移除後再結帳`。
- 提供移除操作。

付款流程需包含：

1. 確認訂單。
2. 顯示匯款資訊。
3. 會員填寫匯款後五碼或上傳匯款資訊，依實際系統功能決定。
4. 狀態進入付款待確認。
5. 後台確認後更新為已付款。

避免使用：

- 多元付款。
- 線上刷卡。
- 即時付款完成。

除非功能已實作，否則不應出現在 UI 文案中。

## 12. 頂部導覽列

建議導覽：

- 首頁
- 販售活動
- 所有商品
- 現貨商品
- 公告
- 會員中心

右側：

- 搜尋。
- 購物車與商品數量。
- 會員頭像 / 姓名縮寫。
- 下拉選單。

未登入狀態：

- 右側顯示 `使用 Google 登入`。
- 需要會員權限的操作點擊後導向 Google 登入。

## 13. 底部服務資訊列

原文案中的 `多元付款` 不適合 MVP。

建議改為：

- 正品來源
- 匯款對帳
- 進度透明
- 會員通知

若國際配送尚未明確支援，不建議顯示 `國際配送`。

## 14. 動畫與互動

整體動畫克制，服務資訊清楚度。

允許：

- 按鈕 hover / pressed。
- 卡片 hover 淡陰影。
- `150-200ms` 顏色與透明度過渡。
- 輕微 transform 或 opacity 變化。

避免：

- 大幅滑動動畫。
- 商品卡跳動。
- 自動播放輪播。
- 飛入式 Banner。
- 過多微互動干擾操作。

可及性要求：

- 支援 `prefers-reduced-motion`。
- Icon-only button 必須有 aria-label。
- 互動元素需有可見 focus state。
- 不能只靠顏色表達狀態，需搭配文字或圖示。

## 16. 空狀態、載入與錯誤狀態

第一階段 Figma 必須包含這些狀態，不列為可選：

- 沒有待辦事項。
- 沒有通知。
- 沒有即將結單商品。
- 沒有販售活動。
- 商品圖片載入失敗。
- 商品已截止。
- 購物車為空。
- 訂單列表為空。
- 付款資料送出失敗。
- Google 登入失敗。
- 權限不足。

空狀態原則：

- 說明目前沒有什麼。
- 說明會員可以做什麼。
- 不使用誇張插圖或促銷語氣。

## 17. 後台 UI 方向

後台與前台目的不同。

前台：

> 品牌感、留白、舒服、容易理解。

後台：

> 資訊密度、效率、搜尋、篩選、批次操作。

後台可參考：

> Notion + ERP

後台需要：

- 高密度表格。
- 快速搜尋。
- 多條件篩選。
- 批次操作。
- 清楚狀態標籤。
- 少動畫。
- Audit Log 與時間軸容易查看。

第一階段後台畫面建議：

1. 商品管理列表。
2. Campaign 管理列表。
3. 訂單管理列表。
4. 訂單詳情與付款確認。
5. 候補管理。
6. 通知 / 公告管理。
7. 會員管理。
8. Audit Log。

後台暫定篩選：

- 訂單狀態。
- 付款狀態。
- Campaign。
- 結單時間。
- 候補狀態。
- 會員關鍵字。

後台規格目前可先納入方向，細節可在後續後台規格書補充。

## 18. 設計原則

### Principle 001

任何 UI 元素都必須有存在的理由。

不要為了讓版面看起來豐富而加入：

- 沒有推薦邏輯的推薦商品。
- 沒有數據支持的人氣排行。
- 沒有折扣的限時優惠。
- 無法操作的裝飾按鈕。
- 過大的無效 Banner。

### Principle 002

會員最重要的事情必須第一眼看得到。

優先順序：

1. 待處理事項。
2. 即將結單。
3. 通知。
4. 販售活動。
5. 一般商品瀏覽。

### Principle 003

結單日期是購買決策資訊，不是附加資訊。

任何會影響是否能下單的頁面，都必須清楚顯示結單時間。

### Principle 004

不要承諾系統尚未支援的服務。

MVP 僅支援銀行匯款與 Google 登入，UI 文案必須反映真實功能。

## 19. 已確認與待確認

### 已確認

- Stone Grey / 暖灰米白方向。
- 避免大面積純白。
- 低飽和狀態色。
- 所有主要卡片使用一致圓角。
- 大桌面 Dashboard 採左欄 / 右欄。

- 右側四個摘要項目在下方右欄範圍內平均排列。
- 任務圖示使用小尺寸。
- 即將結單為登入後首頁核心。
- Dashboard 右側桌面預覽三張卡。
- Dashboard 手機預覽使用橫向滑動。
- 正式商品列表手機一排 2 個。
- 商品卡必須顯示結單日期。
- Campaign 為選填。
- 同一 Campaign 使用同一截止時間。
- 會員一定要 Google 登入。
- MVP 付款方式只有銀行匯款。
- 候補流程需要納入。
- 後台需要納入，但細節可後續修正。

- 候補資格保留期限。
- 訂單是否允許會員自行修改。
- 是否支援海外配送，以及服務範圍。
