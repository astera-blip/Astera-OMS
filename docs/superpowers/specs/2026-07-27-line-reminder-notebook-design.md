# LINE 群組記事本與提醒 Bot 設計規格

日期：2026-07-27
狀態：已完成對話設計確認，待使用者審閱書面規格

## 1. 目標

建立一個獨立於 Astera OMS 的 LINE Bot，讓使用者能用固定指令建立記事與定時提醒。Bot 必須同時支援群組提醒及個人私訊提醒，並提供指定成員、提前預告、完成確認、延後、重複催辦、週期提醒、搜尋、權限與接管功能。

第一階段只供擁有者與 1～3 個白名單測試群組使用，總人數預估不超過 20 人。第一階段以免費額度為主，超過額度後再升級。系統使用繁體中文，所有日期與排程固定採台灣時區。

本 Bot 是獨立專案及獨立資料邊界。第一版不連接 Astera；未來僅透過受保護的 API 與 Astera 整合。

## 2. 明確不在第一版範圍

- 自然語言或 AI 指令解析
- 網頁管理後台
- 圖片、檔案及 LINE 訊息附件保存
- GPS、持續定位或抵達地點觸發
- 多語系與個人時區
- 未互動成員的完整群組名單同步
- Astera 訂單或商品資料串接

## 3. 使用方式

### 3.1 建立提醒

Bot 接受固定格式的繁體中文指令。支援：

- 完整日期時間：`/提醒 2026/07/30 15:00 收單`
- 相對日期時間：`/提醒 明天 09:00 繳費`
- 相對延遲：`/提醒 30分鐘後 關烤箱`
- 週期提醒：`/提醒 每週一 09:00 開會`

提醒文字為必填；地點名稱或地址為選填。地點只作為文字保存與顯示，不提供地圖或抵達提醒。

簡單單次提醒在格式正確時直接建立並顯示結果摘要。下列複雜提醒必須先顯示完整摘要，再由使用者按「確認建立」：

- 週期提醒
- 指定成員
- 提前預告
- 需要完成確認
- 重複催辦
- 自訂延後選項

若指令沒有完整時間，先使用該群組或私聊的預設時間；若沒有預設時間，Bot 顯示按鈕要求補選。年份省略時採下一個合理日期，並在可能歧義時顯示完整日期要求確認。

### 3.2 提醒對象

- 群組內建立的提醒預設發送至該群組。
- 私聊建立的提醒只發送給建立者本人。
- 群組提醒可指定 Bot 已辨識的成員。
- 指定成員時可選擇只在群組標記，或群組標記並同時私訊。
- 私訊僅在該成員可接收 Bot 訊息時執行；無法私訊不影響群組提醒。
- Bot 不要求成員事先登記。第一版僅能辨識曾經加入、發言或操作 Bot，且 LINE Webhook 有提供使用者識別碼的成員。
- 找不到指定成員時，Bot 要求該成員先在群組發言或操作 Bot。

### 3.3 查詢與管理

支援下列指令：

- `/列表`：近期未完成提醒
- `/今天`：今天的提醒
- `/本週`：本週的提醒
- `/已完成`：仍在保存期內的已完成提醒
- `/搜尋 關鍵字`：搜尋仍在保存期內的群組提醒
- `/設定`：群組或個人預設設定
- `/說明`：顯示指令格式與範例

查詢結果中的提醒可依權限顯示「修改、取消、完成、延後」按鈕。所有群組成員都能查看該群組仍在保存期內的提醒；私聊提醒永遠只有本人可見。

## 4. 提醒設定

### 4.1 基本設定

每則提醒可設定：

- 原始提醒時間
- 選填的提前預告時間
- 單次或週期規則
- 是否要求完成
- 完成條件
- 延後選項
- 催辦間隔或指定催辦時間
- 催辦最多次數或最終截止時間
- 選填地點文字

簡短指令建立後，可透過 LINE 按鈕補充進階設定。每個群組亦可設定預設值，建立者可在單一提醒中覆寫。

### 4.2 週期提醒

週期提醒支援三種結束方式：

- 永不結束，直到手動停止
- 在指定日期結束
- 執行指定次數後結束

週期提醒完成時，使用者必須選擇「只完成本次」或「結束整個週期」。「只完成本次」為預設及主要按鈕，以降低誤停整個週期的風險。

### 4.3 完成條件

建立者可為每則提醒選擇：

- 不要求完成：原始提醒成功送出後自動結束
- 任一成員完成：任何一位群組成員按下後整件事完成
- 指定成員完成：只有被指定的成員能完成
- 全員完成：所有被指定成員都需分別完成，並顯示完成名單

### 4.4 延後

- 建立者可延後整個群組提醒。
- 其他成員只能延後自己的提醒。
- 個人延後到期時優先私訊本人。
- 若本人無法接收私訊，則回原群組標記該成員。

### 4.5 催辦與安靜時段

催辦支援：

- 固定間隔，例如每 30 分鐘、每小時或每天
- 指定多個催辦時間
- 最多催辦次數
- 最終催辦截止時間

需要催辦的提醒必須至少設定「最多次數」或「截止時間」，避免無限發送。

預設安靜時段為台灣時間 01:00～06:00，群組管理員可修改。安靜時段只暫停自動重複催辦；使用者明確設定的原始提醒與提前預告仍準時發送。安靜時段內遭暫停的催辦，在時段結束後依序恢復，但不得一次大量補發。

## 5. 權限與治理

### 5.1 一般權限

- 群組內任何成員都能建立提醒。
- 只有建立者能修改或取消自己的提醒。
- 只有符合提醒完成條件的成員能完成提醒。
- 所有按鈕操作都必須由伺服器重新檢查身分、群組與提醒狀態。
- 修改、取消或接管時，群組顯示簡短通知；系統保存完整操作紀錄。

### 5.2 Bot 群組管理員

- LINE 的 Bot 加入群組事件不提供邀請者身分，因此不能可靠地將邀請者自動設為管理員。
- Bot 加入白名單群組後，第一位輸入 `/啟用` 的成員可提出初始管理員認領。
- Bot 擁有者確認認領後，該成員成為首位 Bot 群組管理員；確認前不啟用提醒功能。
- 既有 Bot 群組管理員可新增或移除其他 Bot 群組管理員。
- Bot 擁有者保留緊急管理權。
- Bot 群組管理員是系統內角色，不依賴 LINE 原生群組管理員資料。

### 5.3 接管提醒

提醒只在下列任一情況允許發起接管：

- 建立者已離開群組。
- 接管要求送出後，建立者在群組設定的等待期限內沒有回應。

等待期限預設為 3 天，群組管理員可修改。Bot 會私訊建立者；若無法私訊，則在原群組標記建立者。建立者可在期限內按「拒絕接管」。

建立者沒有拒絕且等待期屆滿後，只要兩位其他群組成員同意，接管成立。接管成立後，新管理者取得該提醒的修改與取消權。接管的發起、同意、拒絕及結果均寫入操作紀錄，並在群組顯示簡短結果。

### 5.4 啟用範圍

測試期只允許白名單群組啟用 Bot。正式開放時再由擁有者決定改為公開邀請或邀請碼，該變更不屬於第一版。

## 6. 排程與發送

### 6.1 排程模型

系統每分鐘執行一次排程工作，查詢已到期且尚未成功發送的事件。事件類型包括：

- 提前預告
- 原始提醒
- 重複催辦
- 個人延後
- 接管等待期到期
- 週期提醒的下一次執行

每個待發事件具有穩定且唯一的事件識別碼。事件處理與發送狀態必須具備冪等性；Webhook 重送、排程重跑、同時執行或網路重試不得造成同一事件重複發送或重複改變提醒狀態。

### 6.2 LINE 額度保護

LINE 主動推播會受官方帳號方案的訊息額度限制，且群組訊息量依收件人數計算。系統必須：

- 保存當月已發送量與失敗原因
- 設定每群組及全域催辦上限
- 接近額度上限時通知 Bot 擁有者
- 額度不足時優先保留原始提醒
- 依序降級：暫停低優先重複催辦，再暫停非必要提前預告
- 不因額度不足而靜默丟棄事件；事件保留為待補發或失敗狀態

實際上限值在部署時依當時的 LINE 台灣方案設定，不硬編碼於程式。

### 6.3 失敗與恢復

- LINE 暫時性發送失敗採有限次數、遞增間隔重試。
- 永久性失敗保存錯誤類型，不進行無限重試。
- 系統恢復後，錯過的提醒一律補發並標示「延遲送達」。
- 延遲超過系統門檻時，另行通知 Bot 群組管理員。
- 補發仍須受防洗版與 LINE 額度保護控制，但原始提醒優先。

### 6.4 Bot 離群

LINE 通知 Bot 已離開群組時：

- 該群組所有未來提醒立即暫停。
- 資料保留 30 天。
- 30 天內重新加入同一群組時恢復提醒，並依故障恢復規則補發錯過事件。
- 超過 30 天未重新加入時，未到期提醒自動取消。
- 取消後資料再依 90 天歷史保存規則處理。

## 7. 資料模型

資料儲存在獨立 Cloudflare 資料庫，至少包含下列邏輯資料單元：

- `users`：LINE 使用者識別碼、顯示名稱、好友／私訊可達狀態、最後互動時間
- `groups`：LINE 群組識別碼、白名單及啟用狀態、離群時間
- `group_members`：Bot 已辨識的群組成員、加入／離開／最後互動狀態
- `group_admins`：Bot 群組管理員
- `group_settings`：預設提醒時間、安靜時段、接管等待期限及催辦上限
- `reminders`：內容、地點、建立者、群組或私聊範圍、狀態及版本
- `reminder_targets`：指定成員與個別完成、延後及通知狀態
- `recurrence_rules`：週期、結束日期或執行次數
- `scheduled_events`：預告、原始提醒、催辦、延後及下一次執行
- `takeover_requests`：發起者、等待期、同意者、拒絕及結果
- `audit_events`：修改前後摘要、操作者、時間及來源
- `delivery_attempts`：發送目標、嘗試次數、結果及錯誤

顯示名稱可能變動，權限與關聯一律使用 LINE 提供的穩定識別碼判斷。

## 8. 保存與隱私

- 已完成或已取消提醒、相關操作紀錄與發送紀錄保留 90 天後自動永久刪除。
- 仍有效的未完成提醒保留至完成、取消或週期終止。
- 私聊提醒不可出現在群組搜尋或群組管理結果中。
- 日誌不得記錄 LINE 密鑰、完整存取權杖或不必要的完整提醒內容。
- 對外錯誤訊息不得暴露內部識別碼、資料庫內容或堆疊資訊。

## 9. 系統架構

第一版採 Cloudflare 獨立 Bot：

1. **LINE Webhook 入口**：驗證簽章、去除重複事件、保存必要事件並快速回覆。
2. **指令解析器**：將固定繁體中文指令轉為明確的提醒草稿或查詢。
3. **提醒服務**：處理建立、確認、修改、取消、完成、週期與權限。
4. **排程服務**：每分鐘查找並鎖定到期事件。
5. **LINE 發送服務**：產生訊息、群組標記、私訊、重試及額度保護。
6. **接管服務**：處理建立者離群、等待期限及兩人同意流程。
7. **清理服務**：執行 30 天離群與 90 天歷史清理。
8. **未來 Astera API 邊界**：第一版不啟用，只保留可驗證及授權的服務介面。

模組間使用明確資料介面。指令解析不直接發送 LINE 訊息；排程服務不直接改寫權限；發送服務不決定提醒業務狀態。這些邊界使各模組能獨立測試及替換。

## 10. 安全設計

- 所有 LINE Webhook 必須使用原始請求內容驗證官方簽章，驗證失敗立即拒絕。
- LINE Channel Secret、Access Token 及管理密鑰只保存於加密環境設定。
- Webhook 事件識別碼必須去重。
- 所有變更操作採版本或交易檢查，避免同時操作覆蓋。
- 所有按鈕資料使用不可偽造或伺服器端可驗證的短效識別碼。
- 每次操作重新驗證操作者、群組、提醒、角色及目前狀態。
- 依使用者、群組及來源限制請求頻率。
- 白名單在執行任何群組業務前檢查。
- 擁有者緊急操作必須完整寫入稽核紀錄。

## 11. 測試與驗收

### 11.1 自動測試

- 完整日期、相對日期、相對延遲、缺省年份及缺省時間
- 台灣時區、跨日、月底、月底週期及閏年
- 單次、每週及具日期／次數結束條件的週期
- 建立者、一般成員、指定成員、管理員及擁有者權限
- 任一人、指定人、全員及不要求完成的狀態轉換
- 完成本次與結束整個週期
- 全群延後、個人延後、私訊失敗後回群組標記
- 固定間隔、指定時間、最多次數、截止時間及安靜時段
- 接管發起、拒絕、兩人同意、建立者離群及等待期
- Webhook 簽章錯誤、事件重送、排程並行及發送重試
- LINE 額度接近、耗盡及恢復
- Bot 離群 30 天內恢復及逾期取消
- 完成／取消 90 天後永久刪除
- 私聊與群組資料隔離

### 11.2 LINE 測試群組驗收

在白名單測試群組完成：

1. 建立單次提醒並準時收到。
2. 建立指定成員提醒，正確群組標記與私訊。
3. 建立週期提醒，完成本次後下次仍存在。
4. 測試三種完成條件。
5. 測試群組及個人延後。
6. 測試安靜時段只抑制催辦。
7. 測試建立者以外成員無法修改或取消。
8. 測試兩人同意的接管流程。
9. 模擬發送失敗後補發且不重複。
10. 移出並重新加入 Bot，確認提醒暫停及恢復。

## 12. 外部平台限制

- LINE 未認證／非高級官方帳號無法透過成員清單 API 取得完整群組成員識別碼；第一版依 Webhook 逐步辨識互動成員。
- LINE 的 Bot 加入群組事件只提供群組來源，不提供邀請者身分；初始管理員改以 `/啟用` 認領及擁有者確認建立。
- Bot 私訊成員前，成員必須處於 LINE 允許接收該官方帳號訊息的狀態。
- LINE 主動推播計入方案訊息額度；回覆訊息與主動推播的計數方式不同。
- 群組訊息會顯示給所有群組成員，不能把同一則群組訊息只隱藏給部分成員。
- Cloudflare 排程以 UTC 設定，應在業務層統一轉換為 Asia/Taipei。

開發與上線前必須再次核對 LINE 台灣當期方案、訊息額度及 Cloudflare 免費方案限制，不將當期數字視為永久規格。

## 13. 成功條件

第一版成功的定義：

- 白名單的 1～3 個群組及個人私聊可穩定使用固定指令。
- 單次與週期提醒在正常運作時於指定分鐘內送達。
- 重試或重複事件不造成重複提醒。
- 建立者、完成與接管權限均無法被一般成員繞過。
- 原始提醒不因催辦安靜時段而延遲。
- 系統故障恢復後會補發並清楚標示延遲。
- LINE 額度不足前可告警，且優先保留原始提醒。
- 私聊內容不會洩漏至群組。
- 歷史資料依 90 天規則清除。
